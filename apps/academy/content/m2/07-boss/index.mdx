  <Step id="intro" title="Pengantar">
    Sepuluh pertanyaan dari seluruh module, sepuluh menit, dan kamu butuh **8 jawaban benar** untuk lulus. Nggak ada feedback sampai akhir, dan urutan pilihan diacak setiap percobaan. Kamu boleh coba lagi sebanyak yang kamu mau.

    Lirik cheat sheet dulu. Ini juga enak dibaca ulang sebelum interview.

    | Topik | Satu baris yang perlu diingat |
    |---|---|
    | Anatomi JWT | `header.payload.signature`, JSON base64url. Bisa dibaca siapa pun yang pegang token, jadi jangan taruh secret. Bearer token. |
    | Claims | Cek `iss`, `aud`, `exp` (dan `nbf`) setiap kali. `sub` adalah user-nya. `kid` memilih key. |
    | Algoritma | HS256 berbagi satu secret, jadi setiap verifier bisa memalsukan. RS256 dan ES256 memverifikasi dengan public key. |
    | JWKS | Public key di URL yang sudah dikenal. Cache, refetch saat `kid` asing, jangan pernah ikuti `jku` atau `x5u` dari token. |
    | Rotasi key | Publikasikan key baru, sign dengannya, pensiunkan key lama setelah token-nya expired. |
    | Access + refresh | JWT access token pendek (5 menit), refresh token opaque berumur panjang, disimpan ter-hash dan bisa di-revoke. |
    | Refresh rotation | Pensiunkan token di setiap pemakaian. Token terpakai yang muncul lagi me-revoke seluruh family (RFC 9700). |
    | Storage | Access token di memory, refresh token di cookie `HttpOnly; Secure; SameSite` dengan `Path` sempit. Jangan pernah localStorage. |
    | XSS | HttpOnly mencegah membaca, bukan memakai. Satu-satunya obat adalah tidak punya bug-nya. |
    | Serangan | Jangan biarkan token memilih algoritma. Pin, ikat key padanya, dan validasi `exp`, `iss`, `aud` (RFC 8725). |
    | Revocation | Revoke refresh token berlaku seketika. Access token hidup sampai `exp`. Revoke instan butuh pengecekan server per request. |
