  <Step id="hook" title="Hook">
    Semua yang sudah kita bahas melibatkan manusia: ada yang login, ada yang klik Approve. Tapi job laporan malam, billing service, atau build pipeline nggak punya manusia dan nggak punya browser. Mereka tetap harus memanggil API, dan API tetap minta token.

    Untuk kasus itu OAuth punya flow yang jauh lebih pendek: satu request, tanpa redirect.

    <Analogy title="Kartu akses karyawan">
      Robot pengantar paket di kantor nggak punya nama atau wajah, jadi dia membawa kartu akses yang hanya membuka pintu-pintu yang boleh dimasukinya. Satpam mengecek kartunya, bukan orangnya. Client credentials adalah kartu itu.
    </Analogy>
  </Step>

  <Step id="concept" title="Konsep">
    **Client credentials grant** (RFC 6749 section 4.4) membuat confidential client bisa mendapat access token **untuk dirinya sendiri**. Nggak ada resource owner, nggak ada halaman consent, nggak ada authorization code.

    <SequenceFlow flow={flows.clientCredentials} />

    Client mengirim `POST /token` dengan `grant_type=client_credentials`, `scope` opsional, dan mengautentikasi dirinya. Cara paling umum adalah HTTP Basic, dengan client id dan secret digabung pakai titik dua lalu di-encode base64 (RFC 6749 section 2.3.1). Jawabannya access token tanpa refresh token.

    Hal-hal yang perlu diingat:

    - **Subject-nya adalah client.** `sub` di token adalah `demo-backend`, bukan user. API tidak boleh memperlakukan token seperti itu sebagai token user.
    - **Scope dibatasi oleh registrasi.** Client boleh meminta lebih sedikit dari yang diizinkan, tidak pernah lebih: `scope=profile` untuk `demo-backend` menghasilkan `invalid_scope`.
    - **Tanpa refresh token.** Client bisa mengautentikasi lagi kapan pun butuh token, jadi refresh token berumur panjang hanya menambah risiko tanpa manfaat.
    - **Secret salah: `401 invalid_client`**, dengan header `WWW-Authenticate: Basic` (RFC 6749 section 5.2).
    - **Hanya untuk confidential client.** Secret harus tetap di server. App browser dan mobile nggak bisa memakai grant ini.

    Perbandingan dua grant utama:

    | | **Authorization code + PKCE** | **Client credentials** |
    |---|---|---|
    | Ada user yang terlibat | Ya, login dan memberi consent | Tidak |
    | Browser dan redirect | Ya | Tidak ada |
    | Token ini tentang | User, diberikan ke client | Client itu sendiri |
    | Autentikasi client | Public: PKCE. Confidential: secret juga | Secret atau key, selalu |
    | Refresh token | Mungkin | Tidak diterbitkan |
    | Pemakaian umum | App milik user yang bertindak atas nama user | Service ke service, job, otomasi |

    <Callout type="warn">
      Shared secret itu password untuk sebuah program. Simpan di secrets manager, jangan pernah di repository atau image, beri tiap service secret-nya sendiri, dan rotasi. Ada client authentication yang lebih kuat, seperti signed JWT assertion atau mutual TLS (RFC 7523, RFC 8705), yang menghilangkan shared secret sama sekali.
    </Callout>
  </Step>

  <Step id="lab" title="Lab">
    Jadilah backend job. Console di bawah memanggil `POST /token` sebagai `demo-backend` (secret `lab-secret`), memakai HTTP Basic.

    <LabTasks />

    <LabConsole
      lab="03"
      actions={[

          label: "Ambil token",

        {
          label: "Minta scope yang nggak dimiliki",
          method: "POST",
          path: "/token",
          headers: { "Content-Type": "application/x-www-form-urlencoded", Authorization: "Basic ZGVtby1iYWNrZW5kOmxhYi1zZWNyZXQ=" },

        },
      ]}
    />

    1. Klik **Ambil token**. Jawabannya `200` dengan `access_token`, `token_type`, `expires_in`, dan `scope`: `photos.read`. Nggak ada `refresh_token`.
    2. Klik **Secret salah**. Kamu mendapat `401` dengan `invalid_client` dan header `WWW-Authenticate: Basic`.
    3. Klik **Minta scope yang nggak dimiliki**. Kamu mendapat `400 invalid_scope`: `profile` nggak termasuk scope terdaftar milik `demo-backend`.
    4. Decode token dari langkah 1 seperti yang kamu lakukan di Modul 2 (isinya JSON base64url di segmen tengah). `sub` dan `client_id` sama-sama `demo-backend`.

    Lalu pakai tokennya. API ada di port lain, jadi salin `access_token` dari console dan panggil dengan `curl` (port `4123` untuk Go, `4223` untuk TypeScript):

    ```bash
    curl -i http://localhost:4123/api/photos -H "Authorization: Bearer TOKEN"
    ```

    API memperlakukannya seperti token valid lainnya: dia mengecek signature, issuer, audience, dan expiry, melihat `photos.read`, dan menjawab `200`. Dia nggak perlu tahu bahwa nggak ada user yang terlibat.
