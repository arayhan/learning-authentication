  <Step id="intro" title="Intro">
    Sepuluh pertanyaan dari seluruh modul, sepuluh menit, dan kamu butuh **8 benar** untuk lulus. Nggak ada feedback sampai akhir, dan urutan pilihan diacak tiap percobaan. Kamu boleh mengulang sesering yang kamu mau.

    Skim checklist-nya dulu. Dia juga bisa dipakai sebagai daftar review OAuth 2.1 dan Security BCP (RFC 9700) untuk sistem nyata.

    | Topik | Satu baris untuk diingat |
    |---|---|
    | Kenapa OAuth | Delegated authorization: token yang scoped, kedaluwarsa, dan revocable sebagai ganti shared password. Bukan authentication. |
    | Role | Resource owner, client, authorization server, resource server (RFC 6749). |
    | Code flow | Front channel membawa **code** sekali pakai. Token kembali lewat back channel. |
    | Tipe client | Public client nggak bisa menyimpan secret (SPA, mobile). Confidential bisa. |
    | PKCE | `code_challenge = BASE64URL(SHA-256(verifier))`, hanya S256. OAuth 2.1 mewajibkannya untuk code flow. |
    | Implicit dan password grant | Sudah hilang di OAuth 2.1. Jangan dibangun di atasnya. |
    | `state` | Nggak bisa ditebak, terikat ke session browser, dicek di setiap callback. |
    | `redirect_uri` | Didaftarkan di awal, dibandingkan dengan **exact string**. Nilai salah: halaman error, tidak pernah redirect. |
    | Scope | Ditegakkan resource server di setiap request. `403 insufficient_scope` untuk token valid yang kekurangan scope. |
    | Code | Umur pendek, sekali pakai, terikat ke client dan redirect URI. Dipakai ulang berarti cabut. |
    | Client credentials | Server ke server, secret milik client sendiri, tanpa user, tanpa refresh token. |
    | Native app | System browser, code flow dan PKCE, jangan pernah embedded web view (RFC 8252). |
    | Token response | `Cache-Control: no-store` dan `Pragma: no-cache` (RFC 6749 section 5.1). |
